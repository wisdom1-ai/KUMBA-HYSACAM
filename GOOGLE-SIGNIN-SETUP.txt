HYSACAM KUMBA TRACKER — CONNECT GOOGLE SIGN-IN

Google sign-in buttons are already connected in the website code for:
- Resident sign in
- Resident account creation
- Administrator sign in (administrator allowlist and six-digit verification remain required)

You must configure Google OAuth once in Supabase and Google Cloud. Do not put the Google Client Secret in website files.

PART A — CREATE GOOGLE OAUTH CREDENTIALS
1. Open https://console.cloud.google.com/
2. Select or create a Google Cloud project
3. Open APIs & Services → OAuth consent screen
4. Choose External (if this is for public residents), enter the app name HYSACAM Kumba Tracker and your support email, then save
5. If Google asks for test users while the app is in Testing, add the Gmail accounts you will use for testing
6. Open APIs & Services → Credentials → Create Credentials → OAuth client ID
7. Choose Web application
8. Add this Authorized redirect URI exactly:
   https://edylcpvigtmyuehje.supabase.co/auth/v1/callback
9. Create the client and copy the Client ID and Client Secret

PART B — ENABLE GOOGLE IN SUPABASE
1. Open your existing Supabase project
2. Go to Authentication → Providers → Google
3. Turn Google on
4. Paste the Google Client ID and Client Secret from Google Cloud
5. Save the provider settings

PART C — ALLOW YOUR WEBSITE CALLBACK
1. In Supabase, open Authentication → URL Configuration
2. Set Site URL to your actual deployed website origin, for example:
   https://YOUR-DEPLOYED-DOMAIN
   Do not include a page path
3. Add this exact URL under Additional Redirect URLs:
   https://YOUR-DEPLOYED-DOMAIN/oauth-callback.html
4. For local testing, add the actual local origin you use, for example:
   http://localhost:5500/oauth-callback.html
   Use your real Live Server port if it is different

PART D — TEST
1. Deploy the updated project to the same website domain
2. Open signin.html and choose Continue with Google
3. Select a Google account and approve the requested access
4. You should return to oauth-callback.html and then enter the resident website
5. Test signup with Google too
6. For administrator Google sign-in, the Google email must already be on the server-side ADMIN_EMAILS allowlist; a six-digit verification code is still required

IMPORTANT SECURITY NOTES
- Keep the Google Client Secret only in Google Cloud/Supabase provider settings
- Never paste the Google Client Secret into index.html, admin.html, or JavaScript
- Do not remove the administrator email allowlist or server-side role checks
- Google sign-in cannot work on an unregistered callback domain
- If Google shows "redirect_uri_mismatch", compare the Authorized redirect URI in Google Cloud character-for-character with the Supabase callback above
- If Google shows "redirect URL is not allowed", add your website oauth-callback.html URL to Supabase Additional Redirect URLs

The website uses the existing Supabase project and existing logo asset. No database schema or account records are changed by this setup guide.
